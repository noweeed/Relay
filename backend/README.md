# Relay Backend

This directory contains everything executed by Relay's backend.

## Structure

```text
backend/
├── src/                 Node.js and TypeScript application
│   ├── config/          Environment, database, logging, and Swagger
│   ├── controllers/     HTTP request/response translation
│   ├── middleware/      Authentication, validation, errors, and rate limits
│   ├── models/          Mongoose application models
│   ├── routes/          Express URL definitions
│   ├── services/        Application and business logic
│   ├── jobs/            Node-owned scheduled/background jobs
│   ├── workers/         Node-owned job workers
│   ├── ai-transport/    Node-to-Python job/result boundary
│   ├── sockets/         Socket.IO setup and events
│   ├── types/           Shared TypeScript types
│   ├── utils/           Small reusable utilities
│   ├── app.ts           Builds the Express application
│   └── server.ts        Connects MongoDB and starts the HTTP server
├── ai-service/          Python 3.12+ LangGraph worker
├── contracts/           Language-neutral Node/Python JSON contracts
├── tests/               Node integration, unit, and fixture files
├── docs/                Backend API documentation
├── scripts/             Operational and setup scripts
├── dist/                Generated JavaScript build output
├── node_modules/        Installed Node dependencies
├── .env.example         Environment-variable template
├── package.json         Node dependencies and commands
└── tsconfig.json        TypeScript compiler configuration
```

## Important generated directories

- `dist/` is generated by `npm run build`. Edit `src/`, never `dist/`.
- `node_modules/` is generated by `npm install`. Do not edit it.
- `ai-service/.venv/` is the local Python environment. Do not edit it.
- Python `__pycache__/` directories are generated automatically.

All generated directories are ignored by the root `.gitignore`.

## Node setup

From `D:\Relay\backend`:

```powershell
Copy-Item .env.example .env
# Add MONGODB_URI to .env
# Add GOOGLE_CLIENT_ID to enable Google sign-in
npm install
npm run dev
```

Useful commands:

```powershell
npm run build
npm run typecheck
npm run lint
npm test
npm run migrate:kanban-columns
```

Endpoints:

- `GET http://localhost:5000/health`
- `GET http://localhost:5000/api`
- `GET http://localhost:5000/docs`
- `GET http://localhost:5000/docs.json`

Current API groups:

- `/api/auth/*` — signup, login, refresh, logout, and current user
- `/api/projects/*` — project CRUD and role-based membership management
- `/api/projects/:projectId/tasks/*` — Kanban task CRUD, filtering, grouping, and activity history
- `/api/projects/:projectId/kanban/columns/*` — owner/admin custom workflow configuration

When MongoDB is connected, `/health` returns HTTP 200 and `database.status: connected`. It returns HTTP 503 when the API is alive but MongoDB is unavailable.

## Python AI worker

See [`ai-service/README.md`](ai-service/README.md). The AI service is a worker behind Node, not a separate frontend-facing API.

For v0.5, set `REDIS_URL` in `backend/.env` and the Python worker's `.env` to the same Redis instance. Node publishes to `AI_JOB_STREAM`; Python returns contract-validated results through `AI_RESULT_STREAM`. Stream names normally keep their provided defaults.

## How the authentication code is organized

Follow one request in this order when learning the code:

1. `src/routes/auth.routes.ts` defines the URL and middleware order.
2. `src/validators/auth.validator.ts` defines accepted input.
3. `src/controllers/auth.controller.ts` translates HTTP details such as cookies.
4. `src/services/auth.service.ts` contains authentication and rotation rules.
5. `src/models/User.model.ts` and `RefreshSession.model.ts` persist state.
6. `src/utils/tokens.ts` signs, verifies, hashes, and compares tokens.

Project requests follow the same route → validator/middleware → controller → service → model pattern.

Task requests follow that same pattern in `task.validator.ts`, `task.controller.ts`, `task.service.ts`, `Task.model.ts`, and `TaskActivity.model.ts`. Task creation and updates use MongoDB transactions so the task and its audit history cannot drift apart.

Kanban columns are embedded in each project because the board contains at most 20 small configuration records. Tasks reference stable column UUIDs. Before starting this code against a database created by the fixed-status implementation, run `npm run migrate:kanban-columns` once; the command is idempotent.
